The problem

SEO plugins often disagree with themselves

A site can emit one canonical URL in the head, submit another in its sitemap, generate a third in schema, and still show analytics-looking numbers that never came from an analytics provider.

Principle 01

Real data or a clear unavailable state

Search Console, GA4, PageSpeed and provider-backed results are only displayed when fetched. Missing data stays unavailable—not replaced with plausible defaults.

Principle 02

One authoritative output

Metadata, canonical resolution, indexability, Open Graph, Twitter cards, JSON-LD and sitemaps share the same resolved content state.

Principle 03

Safe automation by default

Every assistant action passes WordPress capabilities. External interfaces start off, imports support dry runs, and destructive changes require explicit intent.

Rich data, guarded output

Prices, currency, availability, images, attributes, SKU, GTIN, MPN and ISBN are read from WooCommerce objects. Merchant return policy markup remains disabled until the store provides the required policy configuration.

  • Variants link back to their group
  • Offers use live stock and pricing
  • Optional policy data fails closed
Assistant layer

35+ tools, with WordPress still in control

AI clients can inspect and improve SEO without bypassing the site's permission model.

Tool access uses WordPress capabilities and authenticated interfaces. OAuth 2.1 with PKCE is supported, with Application Passwords as a WordPress-native fallback. REST and assistant access are disabled until an administrator enables them.

  • Audit posts, terms, products and archives
  • Read provider-backed analytics and search data
  • Draft metadata and schema changes
  • Run imports in dry-run mode first
  • Compare current and proposed values
  • Reject anonymous and under-privileged requests

Canonical consistency is a shared service

Head output, schema and sitemaps ask one resolver instead of reproducing URL logic in three modules.

Stored builder data is inspected safely

Audits understand supported builders while avoiding front-end shortcode execution and side effects.

Expensive indexes are invalidated, not rebuilt blindly

Content changes mark cached results stale; scheduled or requested work refreshes them within bounded batches.

Compatibility targets real hosting

The codebase maintains a PHP 7.4 floor and WordPress 6.0 baseline rather than assuming a modern managed stack.
